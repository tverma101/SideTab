Your Android tablet, as a real Mac second display.

SideTab creates a virtual macOS display and streams it to Android over USB or a local Wi‑Fi connection, with touch input and high-refresh options for supported hardware.

View source Build from source Project status

Designed as a display pipeline, not a screen-share tab.

The Mac host owns the virtual display and capture/encode path; the Android client owns decode, presentation, input, and device-specific behavior.

USB or local Wi‑Fi

USB uses ADB reverse forwarding for the primary low-variability path. Wireless pairing is available for trusted local networks.

HiDPI display

The maintained fork currently targets a 1400×876 logical HiDPI profile rendered at 2800×1752 physical pixels.

30–120 Hz choices

30, 60, 90, and 120 Hz are exposed. 60 Hz is the normal default; higher modes require real hardware validation.

Hardware video path

VideoToolbox on macOS feeds MediaCodec on Android, using HEVC when supported with an H.264 compatibility fallback.

Touch and S Pen

Tablet touch can control macOS, while the negotiated Samsung S Pen path carries pressure, tilt/orientation, hover, and secondary-button data.

Source-first development

The fork publishes its current state through source, tests, issues, and pull requests rather than presenting unverified performance numbers as guarantees.

Current status

The repository is actively developed. The source version is 0.11.2, with additional unreleased work on main.

Security boundary

Wireless video is not yet end-to-end encrypted. Use wireless mode only on a trusted local network until the Protocol V2/TLS work is complete.

Pairing and control hardening do not make cleartext video traffic private from a network observer.
